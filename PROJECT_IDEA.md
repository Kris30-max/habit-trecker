# PROJECT_IDEA — Telegram-бот «Трекер привычек»

> Мы разрабатываем Telegram-бота с трекером привычек, который следит за прогрессом
> наших правильных привычек.

---

## 1. Проблема

- **Привычки не отслеживаются.** Решение «буду пить 2 литра воды / читать 20 минут /
  делать зарядку» живёт в голове, нигде не фиксируется. Через неделю уже непонятно,
  выполнялась ли привычка вообще.
- **О привычках забывают.** В течение дня внимание уходит на работу и быт,
  и привычка просто вылетает из головы. Без внешнего напоминания она не выполняется.
- **Теряется понимание, зачем это нужно.** Без видимого прогресса пропадает мотивация:
  не видно, что 15 дней подряд — это уже результат, а один пропуск не обнуляет усилия.
- **Существующие приложения перегружены.** Отдельные трекеры требуют установки,
  регистрации, часто платной подписки, и их легко забыть открыть. Telegram же
  открыт всегда.

## 2. Решение

Личный Telegram-бот, который:

1. **Хранит список привычек** — название, расписание (каждый день / по дням недели),
   время напоминания.
2. **Напоминает** в заданное время сообщением с кнопками «✅ Сделал» / «⏭ Пропустить».
3. **Отмечает выполнение** в один тап — без открытия отдельного приложения.
4. **Считает серии (streak)** — сколько дней подряд привычка выполняется,
   и лучшую серию за всё время.
5. **Показывает прогресс** — процент выполнения за неделю / месяц, календарь отметок.
6. **Даёт вечернюю сводку** — что выполнено сегодня, что осталось.

Ценность: привычка отмечается за 2 секунды там, где я и так провожу время;
бот сам напоминает, а статистика наглядно показывает последовательность и прогресс.

## 3. Целевая аудитория

- **Я сам** — единственный пользователь на старте.
- Бот делается под личные потребности, без монетизации и маркетинга.
- Архитектура при этом не запрещает мультипользовательский режим
  (все данные привязаны к `telegram_id`), чтобы при желании дать бота друзьям.
- Доступ на этапе MVP ограничен белым списком `ALLOWED_USER_IDS`.

## 4. Как выглядит продукт (пользовательский сценарий)

### 4.1 Команды

| Команда | Что делает |
|---|---|
| `/start` | Приветствие, регистрация пользователя, выбор часового пояса |
| `/add` | Пошаговое добавление привычки (название → расписание → время напоминания) |
| `/list` | Список привычек с текущими сериями и кнопками управления |
| `/today` | Привычки на сегодня с кнопками отметки |
| `/stats` | Статистика: серии, % выполнения за 7/30 дней, календарь |
| `/edit` | Изменить название / расписание / время привычки |
| `/delete` | Архивировать привычку (история сохраняется) |
| `/settings` | Часовой пояс, время вечерней сводки, вкл/выкл напоминаний |
| `/help` | Справка |

### 4.2 Пример диалога

```
Я:   /add
Бот: Как называется привычка?
Я:   Читать 20 минут
Бот: Как часто? [Каждый день] [Будни] [Выбрать дни]
Я:   [Каждый день]
Бот: Во сколько напомнить? (например, 21:00)
Я:   21:00
Бот: ✅ Привычка «Читать 20 минут» добавлена. Напомню в 21:00.

--- в 21:00 ---
Бот: 📚 Пора: «Читать 20 минут». Серия: 6 дней 🔥
     [✅ Сделал] [⏭ Пропустить] [⏰ Через час]
Я:   [✅ Сделал]
Бот: Отлично! Серия: 7 дней 🔥 Лучший результат: 12.
```

### 4.3 Статистика (`/stats`)

```
📊 Прогресс за 30 дней
Читать 20 минут   ▓▓▓▓▓▓▓▓░░  80%  🔥 7 (рекорд 12)

Вода 2 л          ▓▓▓▓▓▓▓▓▓░  93%  🔥 14 (рекорд 14)
```

## 5. Технические решения

Кратко; полная спецификация — в [TECH_SPEC.md](TECH_SPEC.md).

| Область | Выбор |
|---|---|
| Код | GitHub `Kris30-max/habit-trecker`, CI на GitHub Actions |
| Хостинг | Railway, автодеплой из `main`, Docker |
| БД | Supabase Postgres (Session pooler) |
| Язык / фреймворк | Python 3.12, aiogram 3 (long polling) |
| ORM / миграции | SQLAlchemy 2 async + asyncpg, Alembic |
| Напоминания | собственный тикер раз в минуту, расписание хранится в БД |
| Тесты / линт | pytest + pytest-asyncio, ruff |

## 7. Риски

| Риск | Вероятность | Влияние | Как снижаем |
|---|---|---|---|
| Ошибки часовых поясов: напоминание приходит не вовремя, отметка попадает не в тот день | Высокая | Высокое | Храним время в UTC, дату лога — в локальной зоне пользователя; `zoneinfo`; тесты на границу суток |
| Бот падает / сервер недоступен — напоминания теряются | Средняя | Высокое | Railway restart policy; расписание в БД, тикер догоняет пропущенные напоминания в окне 2 ч |
| Потеря данных в БД | Низкая | Высокое | Supabase Postgres + еженедельный `pg_dump` через GitHub Action |
| Утечка токена бота | Низкая | Высокое | Токен только в `.env`, `.env` в `.gitignore`, при утечке `/revoke` в @BotFather |
| Посторонние пользуются ботом | Средняя | Среднее | Middleware белого списка `ALLOWED_USER_IDS` |
| Неверный подсчёт серий (дни вне расписания, пропуски) | Средняя | Среднее | Чёткие правила подсчёта + юнит-тесты на крайние случаи |
| Разрастание функционала, MVP не доводится до конца | Высокая | Среднее | Жёсткий объём этапов 1–3, всё остальное — в бэклог |
| Сам перестаю пользоваться ботом (напоминания начинают раздражать) | Средняя | Высокое | Гибкие настройки, «Через час», отключение напоминаний, короткие сообщения |
| Лимиты Telegram API при рассылке | Низкая | Низкое | Для одного пользователя неактуально; при росте — очередь и паузы между отправками |

## 8. Критерии успеха

- Бот работает 24/7 без ручного вмешательства не менее 30 дней.
- Напоминания приходят вовремя (отклонение < 1 минуты).
- Отметка привычки занимает ≤ 2 тапов.
- Я веду минимум 3 привычки и отмечаю их ежедневно в течение месяца.
